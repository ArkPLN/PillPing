# 按时吃药（PillPing)

一个简单，易用的服药提醒应用，基于 Expo React Native 构建。

## 技术栈

| 领域 | 选型 |
| --- | --- |
| 框架 | Expo SDK 57 + React Native 0.86 |
| 路由 | Expo Router |
| 语言 | TypeScript + TSX |
| 样式 | NativeWind 4.2.7 + Tailwind CSS 3.4 |
| 状态 | zustand 5 + AsyncStorage  |
| 通知 | expo-notifications |
| 表单 | @react-native-picker/picker + @react-native-community/datetimepicker |
| 图标 | @expo/vector-icons |

## 环境要求

- Node.js 24+ LTS
- Yarn 4
- Android SDK（本地构建 dev client 必须配置）

## 常用开发命令

```bash
# 启用包管理器
corepack enable
# 安装依赖
yarn install
# 安装 Expo / 原生依赖
npx expo install <package>
# 启动开发服务器（Android）
npx expo run:android
# 类型检查
yarn typecheck
# 单元测试（核心排程算法）
yarn test
# Web 预览（仅开发调试，通知能力不可用）
yarn web
```

## 功能

### 今日页

- 顶部显示当日「已服/总数」和进度条；当天没有剂量时显示空状态，按钮会根据是否已有药物显示「添加药物」或「管理药物」。
- 时间线按到点时间升序排列，同一时刻按药名排序。每条显示时刻、时段标注、药名、用量和状态：待服、已服、已漏服、已跳过。
- 已服显示实际服用时刻；已漏服显示已经过多长时间；有推迟记录时显示推迟后的到点时间。
- 下一个待服或漏服剂量会高亮；高亮的是漏服剂量时，卡片使用琥珀色。
- 点击剂量进入「本次服药」：记录本次已服、推迟 10 分钟、跳过本次、补登实际服用时间。已服或已跳过可以撤销。
- 比计划时刻提前 30 分钟以上点击「记录本次已服」，会先弹出确认。
- 页面下方列出过去 3 天的服药摘要（没有剂量的日期不显示），以及药物入口（显示药物总数和启用数）。
- 连续使用达到 3 天，标题改为问候语；达到 7 天，副标题显示已坚持天数。提醒总开关关闭时显示「提醒已暂停」。

### 药物与计划

每种药物有自己的计划，不再有全局次数或间隔。药物页的卡片显示剂型、用量、服用方式、计划摘要、疗程和复诊；右侧开关可停用或启用，停用后仍保留在清单里。

药物表单包含药名、每次用量（数量 + 单位）、剂型、服用方式、计划、疗程、复诊和备注。用量数量支持「半」「1.5」等写法。计划支持三种类型：

- **每天固定**：按槽位列出每天的提醒时刻。每个槽位可单独设置时段标注（起床/早/中/晚/饭前/饭后/睡前）、数量和单位；数量留空时使用药物级的值，单位默认与药物级一致。
- **按周循环**：选择生效的星期，按同一组时刻提醒。
- **按间隔**：设置服药间隔（1–72 小时）、每天次数（1–12）和首剂时间。下一次 = 该药最近一次实际服用时间 + 间隔。每天生成的数量不超过「每天次数」，链条可以跨天。例如间隔 5 小时：
  - 第 1 次 08:00 服用 → 第 2 次计划 13:00；
  - 第 2 次实际 14:00 才服用 → 第 3 次改为 **19:00**；
  - 第 3 次实际 20:30 才服用 → 第 4 次改为 **01:30**。

计划编辑器提供「每日一次/两次/三次」模板，模板区的「饭前/饭后」选项决定生成的时刻：

- 每日一次：08:00；
- 每日两次：08:00、18:00；
- 每日三次：08:00、12:00、18:00；
- 选择「饭前」时，每个时刻提前 30 分钟。

模板生成新的槽位，应用后可以逐条修改。计划可以「存为模板」，之后在其他药物上一键套用；套用是复制，不会和原计划联动。编辑器底部实时预览各槽位的时刻与用量。

疗程为「连续服用天数」，填 0 表示不启用。复诊提醒可选不提醒、第 1/3/5 天或 1–4 周。

### 补登

在「本次服药」页可以为某一次剂量补登实际服用时间，时间选择器只接受当前时刻之前的时间。

- 每天固定、按周循环：记录实际服用时刻，计划时刻不变。
- 按间隔：补登时刻成为新的锚点，下一次 = 补登时刻 + 间隔。
- 已漏服的剂量也可以补登。

特殊用药同样支持补登，入口在各自卡片上的「补登」。

### 特殊用药

底部「特殊」页用于不按循环日历服用的药。特殊用药独立提醒，不计入「今日」的服药次数和进度。支持三种形态：

- **一次性（单日内多次）**：选择一个日期，再添加当天的多个时刻。
- **每周 N 次**：设置每周目标次数和提醒间隔（每 N 天推进一剂）。本周达到目标后，下一剂排到下周。
- **指定日期**：添加一个或多个日期，共用一组时刻。

卡片显示形态、下一次到点时间（超时会标注已过多长时间）和完整节奏；右侧开关可停用。有下一剂时，可以直接「已使用」「推迟」或「补登」。编辑页在有记录时会列出最近的记录和下一次时间。

### 提醒

- 普通药按每药每槽位排定通知，预排未来 48 小时；按间隔的计划只排下一个待服剂量。
- 特殊用药只排下一剂；复诊只排最早一条。
- 通知按钮：普通药和特殊用药为「已服用」「10 分钟后」；复诊为「已复诊」「明天再提醒」。
- 应用启动、回到前台，以及记录、跳过、推迟、补登、保存计划、切换提醒开关后，都会重新同步通知。
- 设置页的提醒总开关会暂停普通药、特殊药和复诊提醒，记录保留。

### 设置

- 提醒总开关。
- 外观：跟随系统、浅色、深色。
- 开始指南：检查添加药物、通知权限、通知横幅、勿扰模式、精确提醒、后台运行和厂商自启动，逐项提供跳转；底部可以安排 10 秒后台测试。
- 提醒权限状态与快捷入口：通知权限、通知样式、勿扰模式、电池与后台、应用设置。
- 测试：立即发送、10 秒后台测试、预览下一次提醒。
- 数据：清空今日记录（保留药物和历史）、清空全部数据。
- 版本信息与致谢。

### 升级说明

存储版本为 3，与旧版数据结构不兼容。旧版本升级后，首次启动会提示重新添加药物并设置服药时间；设置页保留「清空全部数据」入口。

## 与 legacy 版本的差异

| 项 | 原 Java 版 | 本版本 |
| --- | --- | --- |
| 排程模型 | 全局一条链（次数 + 间隔 + 第一次时刻） | 每药独立计划（每天固定 / 按周循环 / 按间隔） |
| 闹钟模型 | 链式单闹钟（触发后再排下一次） | 每药每槽位一次性通知，未来 48h 预排，启动/状态变更时全量同步 |
| 特殊用药 | 按间隔 / 每天固定 | 一次性 / 每周 N 次 / 指定日期 |
| 数据迁移 | — | v3 结构不兼容旧数据；升级时重置并提示重新配置 |
| 签名钉扎 | 启动校验 APK 证书 SHA-256 | 移除；由 Android v2/v3 签名机制在安装时校验 |
| 厂商自启动 | 跳设置页 | 同样只能跳设置页，无法回读状态 |
| 时区变更重排 | BootReceiver 监听 TIME_SET | 应用回到前台时兜底重同步 |
| 应用体积 | ~117 KB | 预计 8–15 MB（RN 运行时开销） |

## 后台提醒

应用使用 `expo-notifications` 的本地通知与精确闹钟（`SCHEDULE_EXACT_ALARM`），不依赖推送服务、不联网。

系统侧仍需用户开启：

1. **通知权限**：设置 → 应用 → 按时吃药 → 通知 → 允许通知
2. **精确提醒**：设置 → 应用 → 特殊应用权限 → 闹钟和提醒 → 允许
3. **后台运行**：设置 → 电池 → 后台耗电管理 → 按时吃药 → 允许后台运行

国产手机（vivo / OPPO / 小米）建议额外允许「自启动」「后台高耗电」「锁屏显示」。应用内「开始指南」会逐项检查并提供跳转。

### 后台测试

设置 → **后台测试提醒**：

1. 点「测试」；
2. 按 Home 退出应用（或锁屏）；
3. 等 10 秒。

如果收到「后台测试提醒 · 成功」，说明后台链路正常。

## 权限说明

| 权限 | 用途 | 不开启的后果 |
| --- | --- | --- |
| `POST_NOTIFICATIONS` | 到点弹出提醒 | 收不到提醒 |
| `SCHEDULE_EXACT_ALARM` | 按分钟准时触发 | 系统可能延迟几分钟 |
| `RECEIVE_BOOT_COMPLETED` | 重启后恢复已排通知 | 重启后可能不再提醒 |
| `VIBRATE` / `WAKE_LOCK` | 振动与唤醒 | 提醒可能无声音 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 引导加入电池白名单 | 长时间后台可能漏提醒 |

暂无 `INTERNET` 权限

## 开发说明

- **Web 端仅用于开发预览**：`expo-notifications` 的原生能力在 web 不可用，通知层在 web 上会自动降级为 no-op（见 `src/lib/notifications/platform.ts`），`@react-native-community/datetimepicker` 也不支持 web。
- **路由类型**：启用了 `experiments.typedRoutes`，新增页面后若类型未更新，删除 `.expo/` 重新生成。
- **测试**：`src/lib/__tests__/` 使用 Node 原生 test runner（经 `tsx` 执行），与 RN 运行环境隔离。
