# 按时吃药 · 服药提醒 v1.6.2

一个只在本地运行的 Android 服药提醒小工具。默认适合「每天 3 次、第一次起床后服用、之后每隔 5 小时一次」，也支持自定义 **1–12 次/天**、自定义间隔，以及独立的**特殊用药**提醒。

## 版本命名

- 1.6.x：1.6 系列的修正版本，x 为修改次数（当前 1.6.2）。
- 1.6.0 加入了服药周期、复诊提醒和提醒总开关，属于重要功能更新。
- 后续只有再加入重要功能时才提升前缀，例如 1.7。

## 剂型与图标

- 添加/编辑药物时提供「药片、胶囊、口服液、注射剂、外用、其他」六种剂型。
- 选择剂型时图标会淡出/淡入切换，药片、胶囊、药瓶、注射器等各自有对应图标。
- 药物列表和特殊用药列表会用剂型图标代替首字头像。
- 旧药物没有剂型字段时会根据名称、用量和服用方式自动推断。

## 深色模式

- 设置 → 外观：跟随系统 / 浅色 / 深色。
- 默认跟随系统，系统切换深色时应用自动同步。
- 主页面、弹层、输入框、时间选择器、状态栏和导航栏都做了深色适配。

## 服药周期与复诊

- 每种普通药物可设置「连续服用天数」：0 = 长期，或 7 / 14 / 30 / 90 天及自定义。
- 点数时可以直接输入天数，不需要连续点 +/-；服药间隔也提供常用小时快捷选择。
- 到期后该药自动从提醒中排除，不再生成服药提醒。
- 可单独设置「复诊间隔」：不提醒 / 每 14 / 30 / 90 天及自定义。
- 复诊提醒只在药物疗程内生效，通知栏可直接点「已复诊」或「明天再提醒」。
- 设置 → 提醒总开关：一键暂停普通药、特殊药、复诊的全部提醒，记录保留。

## 连续使用问候

- 设置页不需要额外开关：应用会记录连续打开使用的天数。
- 连续使用满 3 天后，主界面标题会按系统时间显示「早上好 / 中午好 / 下午好 / 晚上好 / 夜深了」。
- 满 7 天后，副标题会显示「已坚持 N 天」。
- 中间断一天会重新从第 1 天计算。

## 屏幕兼容

- 使用 dp/sp 布局，适配 320dp 小屏、常见 360/412dp 手机和 600dp+ 平板。
- 小屏下设置项的步进器会自动换行，避免挤压。
- 平板/大屏内容最大宽度 640dp，底部弹层最大 560dp，避免文字被拉得过长。
- 所有主页面和弹层都支持纵向滚动、横屏和字体缩放。

## 应用安全

- APK 使用 v2/v3 签名，更新只能由同一证书签名。
- 启动时校验证书 SHA-256，签名不一致或 debuggable 构建会停止运行。
- 所有闹钟/通知接收器也做签名校验，避免被替换组件直接调用。
- 没有 INTERNET 权限，没有动态加载代码，没有导出多余的组件；`allowBackup=false`。
- APK 更新沿用固定 keystore，后续版本可覆盖安装保留数据。
- 注意：没有绝对安全；请只从可信来源安装，并核对 APK 哈希/证书。

## 通知与动效

- 采用「有感而无扰」：高重要性通知、声音、振动、横幅、锁屏/息屏通知，不弹出全屏页面。
- 通知使用 `CATEGORY_REMINDER`，不占用全屏通知权限，也不会打断正在使用的应用。
- 底部弹层增加进入/退出动画；切换「今日 / 药物 / 特殊」时内容淡入上移。
- vivo 原子岛 / 原子通知由系统控制，第三方应用没有公开 API 可以直接唤起。
- 主页面不再显示权限/勿扰提示；提醒状态统一放在设置页，避免干扰。

## 兼容性与电量

- 最低 Android 8.0（API 26），目标 Android 14（targetSdk 34），已在 Android 16 / vivo 上运行。
- 通知、精确闹钟、电池白名单、开机恢复都按 Android 8–16 的版本差异做了兼容处理。
- **同一时间只保留一个普通服药闹钟**：闹钟触发后，接收器再排下一次，避免为未来 12 次同时挂 12 个精确闹钟。
- 通知接收器只持有约 5 秒 WakeLock，发完通知立即释放。
- 没有常驻前台服务、没有轮询、没有网络请求；后台耗电主要来自每次到点的一次闹钟唤醒和通知。
- 特殊用药每种只保留一个下一次闹钟，和普通服药互不影响。

## 先看这里：后台提醒

吃药提醒不需要一直把应用挂在前台。应用使用的是：

- `AlarmManager.setAlarmClock()` 精确闹钟；
- 通知权限；
- 精确提醒权限；
- 电池优化白名单；
- 开机自动恢复闹钟；
- 收到闹钟后使用 `WakeLock` 唤醒并弹出通知。

但 Android 厂商（尤其 vivo / OPPO / 小米）还有自己的后台限制，应用无法替用户打开。**开始指南**里会逐项检查并跳转到对应设置。

### 用「后台测试」确认

设置 → **后台测试提醒**：

1. 点“测试”；
2. 按 Home 退出应用（或锁屏）；
3. 等 10 秒。

如果仍收到“后台测试提醒 · 成功”，说明当前后台链路正常；如果没有，按指南检查通知、精确提醒、后台运行和自启动。

## 开始指南

首次打开会出现「开始指南」，也可以在 **设置 → 开始指南** 再次打开。指南会检查：

1. 是否已添加药物；
2. 通知权限；
3. 通知横幅 / 锁屏显示；
4. 精确提醒；
5. 后台运行（电池优化白名单）；
6. 自启动 / 后台高耗电（需要手动设置）。

每一项都有状态和跳转按钮；最后可以直接做 10 秒后台测试。

## 核心规则

### 1. 普通服药：链式排程

下一次服药不是固定按第一次推算，而是：

> **下一次时间 = 最近一次实际服药时间 + 服药间隔**

例如间隔 5 小时：

- 第 1 次 08:00 服用 → 第 2 次计划 13:00；
- 第 2 次实际 14:00 才服用 → 第 3 次自动改为 **19:00**，而不是 18:00；
- 第 3 次实际 20:30 才服用 → 第 4 次自动改为 **01:30**。

### 2. 补登：忘记点“已服用”也没关系

如果已经服过药但忘记登记，可以在对应次数里选择 **补登**，填写实际服用的时间。补登后会按那个实际时间重新计算下一次，而不是按现在的时间硬记。

- 首页“下一次服药”下方有“忘记登记？补登本次实际时间”入口；
- 每次服药的详情页里也有“补登实际服用时间”；
- 已经记录过的次数，可以“修改服用时间”；
- 补登只能选择过去的时间，且不能早于上一次服药时间。

### 3. 特殊用药：单独页面、独立节奏

底部 **「特殊」** 页用于不按普通方案服用的药，不会出现在“今日”时间轴里，也不影响普通服药次数。

支持两种模式：

- **按间隔**：每 1–72 小时一次，从最近一次实际服用时间开始计算；
- **每天固定时间**：例如每天 21:00。

每种特殊用药都有独立的“已服用 / 补登 / 推迟”操作和独立通知。

## 怎么用

1. 打开 App，按「开始指南」检查通知和后台设置。
2. 在「药物」页添加普通药品：药名、每次用量、服用方式，并选择“每次”或指定第几次。
3. 去「设置」可调整每天次数（1–12）和间隔（1–12 小时）。
4. 起床吃完第一次药后，在「今日」页确认时间，点 **记录第一次服药**。
5. 之后到点会收到通知；通知栏可直接点 **已服用** 或 **10 分钟后**。
6. 如果忘了登记，点首页的 **补登** 或进入对应次数选择实际时间。
7. 如果某种药节奏特殊，去底部 **特殊** 页单独添加。

## 系统设置清单

### 必须开启

- **通知权限**：设置 → 应用 → 按时吃药 → 通知 → 允许通知。
- **精确提醒**：设置 → 应用 → 特殊应用权限 → 闹钟和提醒 → 允许。
- **后台运行**：设置 → 电池 → 后台耗电管理 → 按时吃药 → 允许后台运行 / 不受限制。

### 建议开启（国产手机）

- **自启动**：设置 → 应用 → 自启动管理 → 按时吃药 → 允许。
- **后台高耗电**：设置 → 电池 → 后台高耗电 → 按时吃药 → 允许。
- **锁屏显示**：设置 → 通知与状态栏 → 按时吃药 → 锁屏通知 → 显示。
- **横幅**：通知设置 → 服药提醒渠道 → 允许横幅 / 悬浮通知。

### 如果还是没有横幅

部分 vivo 手机会把应用级“横幅 / 锁屏”默认关闭，即使通知渠道重要性是“高”。到：

> 设置 → 通知与状态栏 → 按时吃药 → 允许通知、允许横幅、锁屏显示

再把“服药提醒”渠道的重要性设为“高”，并关闭静音/勿扰。

## 功能

- **后台提醒**：精确闹钟 + 通知 + WakeLock，不要求应用一直前台。
- **后台测试**：10 秒后触发一条通知，按 Home 后验证。
- **开始指南**：逐项检查通知、横幅、精确提醒、后台运行、自启动。
- **链式排程**：每次实际服药后，下一次从实际时间重新计算，并自动重排后面所有未服次数。
- **补登 / 修改时间**：支持回到实际服用时间登记，并重排后续提醒。
- **次数可调**：普通服药 1–12 次/天；修改后今天尚未服用的次数会立即重排。
- **特殊用药**：独立页面，支持每 N 小时或每天固定时间，独立提醒。
- **药物清单**：药名、用量、服用方式、备注；可指定“每次”或某几次；可停用、编辑、删除。
- **今日时间轴**：待服用 / 已服用 / 已推迟 / 已跳过 / 已超时。
- **跨天**：晚服或次数较多时，会自动标出“明天”。
- **到点通知**：高优先级通知 + 声音 + 震动；支持“已服用”“10 分钟后”快捷操作。
- **历史记录**：保留最近 40 次普通服药记录。
- **本地存储**：不联网、不上传；`allowBackup=false`。

## 权限说明

| 权限 | 用途 | 不开启的后果 |
| --- | --- | --- |
| 通知权限 | 到点弹出提醒 | 收不到提醒 |
| 精确提醒（闹钟和提醒） | 按分钟准时触发 | 系统可能延迟几分钟 |
| 后台运行 / 忽略电池优化 | 避免被系统冻结 | 长时间后台可能漏提醒 |
| 自启动（厂商设置） | 开机/清理后台后恢复 | 重启后可能不再提醒 |

## 注意

- 如果在系统设置里「强制停止」本应用，系统会清空已经排好的闹钟；重新打开 App 会自动恢复未来的提醒。
- 部分手机会把后台应用冻结。若发现提醒变晚，请务必允许「自启动 / 后台高耗电 / 不受限制」，并在 App 开始指南里打开「精确提醒」。
- 修改普通服药次数时，如果减少次数会删掉今天已经记录的后几次，App 会先二次确认。
- 特殊用药的“每天固定时间”在记录服用后，下一次会排到明天同一时间，避免同一天重复提醒。

## 关于更新不丢数据

Android 只有在 **新 APK 与已安装 APK 使用同一签名证书**、且 `versionCode` 更高时，才允许覆盖安装并保留数据。

- 从 v1.5 起应保存固定的签名 keystore，后续版本用它签名，就能直接覆盖升级、保留药物和记录。
- v1.3 的签名密钥在重建构建环境时丢失，因此 v1.4/v1.5 不能直接覆盖 v1.3；首次切到 v1.5 需要卸载一次（会清数据）。
- 切到 v1.5 之后，只要后续版本继续使用同一 keystore，就可以正常覆盖升级。

## 构建

本项目不使用 AndroidX / Gradle，直接用 Android SDK 工具构建（Termux 内可完成）：

```bash
# 需要：openjdk-21、aapt2、d8、apksigner、android.jar（API 35）
cd MedReminder
bash build.sh
```

产物：`medtimer.apk`。
