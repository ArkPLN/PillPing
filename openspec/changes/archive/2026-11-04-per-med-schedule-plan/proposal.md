# Proposal

## Why

当前版本沿用 legacy 单人工具的设计：全局唯一的「每天 N 次 + 间隔 + 第一次服药时刻」链条决定所有人的服药时间，药物只能挂到第几次（`slotMask`），不能指定自己的时刻。对单药单节奏的原始作者这是合理的；但对多数真实用户——多种药物、各自时间和频次互不相同——这个全局配置不成立。本变更加以 v3 重构：**每种药物拥有唯一且独立的服药时间计划**，全局时间配置退场。

## What Changes

- **BREAKING — 每药独立计划，取消全局时间配置**
  - `Med` 增加唯一计划字段 `plan`，替代 `allDoses` / `slotMask`；全局 `interval` / `doseCount` 与全局 `Cycle`（今日轮次）从数据模型中移除。
  - 设置页删除「每天服药次数」「服药间隔」两项；首页删除「第一次服药时间」开工流程。
  - **不考虑数据迁移与 legacy 兼容**：以新版本存储结构为准，旧数据不转换、不保留（用户已确认）。
- **新增常规服药计划模块**（内联于药物，可另存为模板）
  - 计划类型三种：`daily`（每天固定时刻）、`weekly`（按周循环）、`interval`（按间隔，收编原链式语义，锚点 = 该药自己最近一次实际服用时刻）。
  - 默认模板「每日一次 / 两次 / 三次」，可与「饭前 / 饭后」组合：饭后默认 08:00 / 12:00 / 18:00，饭前在默认时刻基础上**向前偏移 30 分钟**；模板应用后用户可逐时刻修改（时刻、用量、标签）。
  - 模板为**复制语义**：应用时拷贝进药物，之后各自独立，不随模板变更联动。
  - 按周循环 v1 精度：选定星期几 + 该组统一的一套时刻；每天不同时刻留待后续版本。
  - 每个时刻（槽位）可单独配置用量（如早 1 片、晚 2 片），缺省回退到药物级用量。
- **漏服语义**：固定时刻表下，计划时刻已过且未记录 = 派生状态「已漏服」，与用户手动「跳过」区分展示；均不影响其他时刻的派生计划。
- **首页重构为今日时间线**：按时刻聚合当日全部剂量（已服 / 待服 / 已漏服 / 已跳过），顶部聚合进度 = 各药当日剂量求和；无任何启用药物的药物时为「无计划」空态并引导添加。
- **特殊用药重新定义与扩展**
  - 定位收窄为**非常规计划**：不能用「循环日历 + 固定时刻」表达的场景。判定特征是「不规则 / 按事件计数 / 跨周」，而非病种。
  - 仅保留三种形态：`once`（一次性，单日内可多次）、`weekly-count`（一周内达到 N 次）、`dates`（指定日期，单选或多选）；`interval` / `daily` 不再归入特殊用药，由常规计划承担。
  - 状态模型从单点 `nextAt` 升级为**记录列表**，支持补登、连漏与历史追溯。
- **表单控件与页面规范（KISS）**
  - 固定枚举字段一律使用下拉选择：计量单位、剂型、服用方式、复诊提醒、计划类型、时机标签、特殊用药模式。
  - 明确为数值的字段使用文本输入框（默认支持小数，也接受「半」等数字文本）；用量拆分为「数量（文本输入）+ 单位（下拉选择）」。
  - 时间、星期、日期分别使用专用选择器，不得用文本输入替代；类型不明确时默认文本输入框。
  - 页面不写解释性小字，仅在语义不可自明处保留一句；减少分组与注释，保持直接。
- **通知调度改造**：由「全局 ≤12 条一次性 trigger」改为「每药每槽位一条」，只预排未来 24–48 小时内的剂量，应用启动 / 任意记录动作 / 计划编辑后全量重排（沿用 `syncAll` 骨架，替换输入源）。
- **规格与不变量更新**：`legacy JSON 字段对齐`的不变量废止；`cycle.test.ts` 的三个 legacy 链式示例由 interval 型计划以每药粒度继承钉住。

## Capabilities

### New Capabilities

- `med-plan`：常规药物服药计划模型（计划类型、时刻槽位、用量、标签、模板）与每药计划的派生、记录、漏服判定。
- `home-timeline`：首页今日时间线的聚合、状态展示（待服 / 已服 / 已漏服 / 已跳过）、进度与空态。
- `special-irregular`：特殊用药（非常规计划）的定位边界、三种形态（一次性 / 每周计数 / 指定日期）、记录列表与提醒。
- `form-controls`：表单控件选择规则（枚举下拉、数值文本、时间/星期/日期专用选择器、模糊默认文本）与页面文案最小化。

### Modified Capabilities

- `cycle-scheduling`：链式锚定规则从全局单链改为每药 interval 型计划内的规则；全局 Cycle 的「修改间隔 / 次数后重排」需求删除；「推迟感知的到点时间」语义扩展到每药计划域。
- `time-precision`：秒级精度约束的对象从「全局周期」扩展为「每药计划派生」，既有文案精度要求不变。
- `shared-foundation`：常量与工具归置新增计划槽位 / 星期掩码等常量；通知 identifier 前缀方案随「每药每槽位」调整。

## Impact

- **领域层**（`src/lib/`）：`cycle.ts`（全局链式派生 → 每药计划派生，interval 型保留锚点链）、`med.ts`（slotMask 位操作 → plan 槽位）、`types.ts`（新增 `SchedulePlan` / `DoseRecord`，`Med` 扩展，`Cycle` / `interval` / `doseCount` 移除）、`specialmed.ts`（三种形态与记录列表）、新增 `plan.ts`（计划派生与今日聚合）。
- **状态层**（`src/store/useStore.ts`）：`interval` / `doseCount` / `cycle` 状态与对应 actions 移除；`startCycle` / `markTaken` 等改为 `(medId, slot, dateKey)` 粒度；存储 `version` 递增且不迁移旧数据（加载旧结构时按空数据重置）。
- **页面层**（`src/app/`）：`med-form.tsx`（计划编辑器，按 `form-controls` 规则选型）、`special-form.tsx`（三形态）、`settings.tsx`（删除次数 / 间隔两项）、`(tabs)/index.tsx` + `Hero.tsx` + `HomeCards.tsx`（今日时间线重构）、`time-picker.tsx`（first 模式删除，backfill 改为 med+slot 粒度）、`dose.tsx`（从全局 index 改为 med+slot 寻址）。
- **表单组件层**（`src/components/`）：新增计划编辑器与用量（数量 + 单位）组件；枚举字段统一下拉选择，时间 / 星期 / 日期分别使用专用选择器。
- **通知层**（`src/lib/notifications/`）：`input.ts` / `scheduler.ts`（输入源从 Cycle 改为每药计划 + 24–48h 预排窗口）、`response.ts`（action 携带 medId+slot）。
- **测试**：`cycle.test.ts` 重写（interval 型每药链式案例继承钉住）；新增计划派生、漏服判定、聚合、特殊用药计数的单测。
- **文档**：README 与 AGENTS.md 的「legacy 字段对齐」「链式排程」章节更新为 v3 表述。
